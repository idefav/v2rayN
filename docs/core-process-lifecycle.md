# 内核重启与进程清理

重启事务按以下顺序执行：生成候选配置，停止并验证旧主／前置内核，检查新配置的监听占用，替换正式配置，启动并验证新实例。停止失败时不替换正式配置、不启动新实例；下一次操作重试保留的进程记录。

## 进程所有权与停止结果

- 每个 `ProcessService` 持有独立的启动标识、PID、启动时间、可执行文件和配置路径。提权启动使用带唯一标识的内部消息报告实际内核身份，sudo 包装进程和内核分别记录。记录仅在当前会话有效，不建立持久化残留回收清单。
- `StopAndWaitAsync()` 返回 `ProcessStopResult`。状态区分成功、超时、权限不足、身份变化和其他失败；失败结果保留尚未确认退出的进程。兼容的 `StopAsync()` 复用同一停止逻辑并报告错误。
- Unix 停止前保存进程树，父进程退出后仍继续验证已记录的子进程。SIGTERM 最多等待 5 秒，随后对身份仍匹配的进程发送 SIGKILL 并验证最多 3 秒；每个内核的总停止预算为 10 秒，包含提权和进程查询。僵尸进程按已退出处理。
- macOS/Linux 停止脚本接收成对的 PID／启动时间参数。脚本在发信号前核验身份，输出 `IDENTITY` 记录供调用方保留，输出 `STAGE` 供日志记录阶段。退出码 20 表示身份变化，21 表示信号或权限失败，22 表示退出超时，23 表示参数或枚举失败。
- 已退出的包装进程先等待输出读取完成，避免丢失迟到的内核身份消息；确认所有目标已退出后直接成功，不再要求一次多余的 sudo 授权。
- Windows 使用进程树快照和启动时间核验，终止后有界等待所有已记录目标退出。`Dispose()` 不代替退出确认，失败对象与临时文件会保留；应用退出时重试未完成的临时内核清理，并记录失败。

## 启动与诊断

- `CoreManager` 内部串行化启动与停止，继续兼容界面已有的重载协调器。主／前置内核分别清理，一个失败不跳过另一个；部分停止会使有效配置快照失效。
- sing-box 监听检查覆盖 mixed／SOCKS、额外入站、Clash API 和 V2Ray API，区分 TCP／UDP、地址族、通配地址和 IPv6 专用监听。不把已连接套接字或 TIME_WAIT 当成监听占用。
- 发现占用时中止启动，尽量显示 PID 和程序信息。权限不足时明确说明信息不可读取，不按名称或端口自动终止未知进程。
- 生成配置的启动确认同时检查实际内核存活、启动身份和适用的本地 SOCKS／监听状态，启动预算为 10 秒。未声明可探测入口的自定义配置保留原有存活检查，不强制增加管理 API。
- 启动失败会清理本次已启动的主／前置内核；清理失败仍保留记录。错误经 `LastError` 传到连接控制面板，操作结束后恢复控件。
- `CoreLifecycle` 日志包含启动标识、包装／内核 PID、启动时间、停止阶段、耗时与结果；密码只用于标准输入，不写入命令参数或生命周期日志。

## 回归验证

在仓库根目录执行：

```sh
dotnet build v2rayN/ServiceLib.Tests/ServiceLib.Tests.csproj -c Release
dotnet test --project v2rayN/ServiceLib.Tests -c Release
dotnet build v2rayN/v2rayN.Desktop/v2rayN.Desktop.csproj -c Release -p:UsedAvaloniaProducts=
```

设置 `SSH_TEST_SINGBOX` 指向待验证内核可启用真实内核测试。`ProcessLifecycleTests` 使用隔离配置和随机回环端口，调用生产 `CoreManager` 完成 30 次连续重启，并验证前置内核启动失败后的完整回滚；测试存储必须位于测试程序输出目录。

其他回归覆盖父进程提前退出、孤儿监听子进程、忽略 SIGTERM、缓慢退出、提权失败、帮助进程超时、枚举失败、身份不匹配、正式配置保留、应用退出与排队重启、未知监听、TCP/UDP、IPv4/IPv6 和 TIME_WAIT。

macOS 的直接 TUN／前置 TUN 验证须额外设置 `V2RAYN_TEST_TUN_RESTART=1`，并预先具备非交互 sudo 授权。测试仅使用 `198.18.77.0/30` 隔离路由，不接管默认路由或系统 DNS；如果该测试地址已经经过 VPN／特定路由则跳过，防止覆盖现有连接。未运行提权／TUN 或其他平台测试时，应明确报告，不能用普通进程测试或跨平台编译替代实机结果。
