# 跨核心端口交接与手动重启

macOS 从提权核心切换到普通权限核心时，进程退出不代表端口已可复用。交接依据每个主/前置核心的实际启动权限和监听端点，涵盖 Xray 与 sing-box。

启动顺序为：固定节点/配置/核心/代理端口快照，生成主/前置候选，解析监听并检查候选之间的冲突，通过两份原生配置检查后才停止旧进程。随后等待目标权限能够绑定重叠端口、检查全部候选监听、成对提交正式配置、启动并确认所需核心就绪。解析或原生预检失败保留旧核心；交接取消或超时保留记录供重试，最长等待 90 秒。未知监听占用报错，不终止未知进程，也不自动改端口或提权普通 Xray。

监听模型区分 TUN 设备、固定 TCP/UDP 端口，以及动态 SOCKS UDP。包括 Xray 的 mixed、原生 TUN、metrics.listen 与 api.listen；冲突保留来源标签，并结合本机绑定语义检查通配与双栈地址。端口就绪同时核验已记录的进程身份和监听归属；TUN 额外核验本次预期接口。未确认归属不会报告启动成功。

正式配置的两个备份保留到完整启动成功。任一替换或启动失败，只有新进程全部确认退出后才恢复；退出未确认时保留身份、配置和备份，重试先清理。候选校验进程同样使用独立、有界清理。交接记录按端点保留，成功使用其他端口不会清空旧端点的等待依据。

当前内置 Xray 的 SOCKS UDP 在 UDP ASSOCIATE 时创建动态端口，不将 SOCKS TCP 端口误判为固定 UDP 监听。就绪检查验证无认证 SOCKS 的 UDP ASSOCIATE 响应；带认证的配置只验证认证方法协商，不使用用户凭据发起探测。参考 [Xray SOCKS 握手实现](https://github.com/XTLS/Xray-core/blob/main/proxy/socks/protocol.go)。

连接主页的“重启内核”强制重新加载当前选择和已保存配置；有待应用更改时显示“应用并重启”。仍执行路由兼容性预检。运行中且空闲时可用，未连接、正在切换、等待端口或退出未确认时不可重复执行。主核心及必需的前置核心都就绪后才更新运行摘要；任一必需核心退出显示连接不完整，可以重启恢复。Avalonia 与 WPF 共用运行状态和命令。

核心配置未变时仍核对系统代理，代理失败只重试代理应用；已匹配时跳过写入。代理端口和脚本路径来自本次快照，取消贯穿写入，取消后的读回使用独立期限，显示实际结果。断开请求在前次操作结束后清理代理。自定义脚本无法通用读回时保留原有脚本执行结果语义。

可达性检测绑定实际运行节点、运行代次和代理入口，同节点重启也会使旧结果失效。远端检测失败不触发重启；启动诊断有界保存 stdout/stderr 的错误行，避免缓存完整 JSON 配置。内核就绪与远端可达性分开呈现。

本地测试通过独立临时配置和随机端口运行核心，不需要更改已安装客户端。真实跨 UID/TIME_WAIT 验证依赖隔离提权夹具，普通权限端口占用测试不能替代该验证。
