# sing-box TUN 设置使用说明

Avalonia 客户端入口：**设置 → TUN 模式**。主界面连接控制中的 TUN 开关负责启停；本页负责编辑配置，保存不会自动开启 TUN。

本页面向 sing-box 1.14+，兼容主内核直接接管和 sing-box 前置接管。顶部显示负责 TUN 的内核与版本；无法确认版本时如实显示未确认。Windows WPF 本轮继续使用原设置界面，新增配置在读写时保留。

## 普通使用

1. 保留既有地址、MTU 和协议栈，新增选项优先选择“自动”。
2. 点击选项旁的“使用说明”，查看默认值、取值区别、依赖、例子和排障提示。
3. 修正字段错误，点击“保存并应用”。
4. 有已选节点时，即使 TUN 关闭也会先检查将来启用的配置；关闭状态仅保存，下次开启生效。未选节点时明确提示尚未完成内核预检。
5. 配置未变化时保留连接。配置检查失败不会停掉现有内核；启动失败时尝试恢复上一份设置与有效配置，并明确显示恢复结果。

“使用帮助”支持搜索中文名称、英文参数或使用场景，并可导出完整 Markdown 离线说明。完整逐字段说明由 TunSettingsCatalog 同时提供给界面、搜索和导出，避免帮助与配置脱节。

## 各组怎么用

### 基础与地址

- **协议栈**：保留当前值。gVisor 需要内核编译支持；system 使用系统协议栈；mixed 使用系统 TCP 与 gVisor UDP。
- **MTU**：下拉选择常用值，也可选自定义。先保留原值；遇到特定路径异常再尝试较小值，不会修改物理网卡 MTU。
- **地址**：主 IPv4 / IPv6 保留旧配置兼容，额外地址可逐项添加。顺序保留，关闭 IPv6 时保留但不输出额外 IPv6 地址。
- **设备名**：自动沿用平台行为。macOS 自定义只能使用 utun 加数字；Linux 名称最多 15 字节。
- **严格路由**：只在 Windows / Linux 生效。不适用项默认隐藏，可切换查看只读说明。
- **兼容前置**：其他内核运行节点时，可由 sing-box 前置负责 TUN，不会替换所选节点。
- **TCP 回接**：更多高级选项中的 loopback_address 让访问指定地址的 TCP 连接回接到来源地址，普通使用留空。

### DNS 接管

| 选择 | TUN 行为 |
|---|---|
| 自动 | 保留旧生成行为。内核在自动路由开启时默认 hijack，关闭时默认 disabled；原有应用路由行为保留。 |
| 劫持 hijack | 配置接口 DNS，并接管 TUN 入站的 DNS 请求。 |
| 原生 native | 配置接口 DNS，仅自动处理发往虚拟 DNS 地址的请求；其他目标 DNS 按普通路由处理。 |
| 关闭 disabled | 不自动配置或接管该 TUN 入站的 DNS，适用于其他服务管理 DNS。 |

显式模式同步调整 v2rayN 生成的接管规则；混合代理端口的 DNS 与用户显式路由独立保留。

**虚拟 DNS 地址不是公共上游 DNS。** 例如 TUN 为 172.18.0.1/30，留空时自动推导入口 172.18.0.2。上游在“DNS 与流量出口”设置。指定虚拟入口后，生成器补齐路由；入口不能与 TUN 自身地址相同。

native / disabled 可能改变 DNS 实际出口，应配合代理检查验证；这些选项不承诺阻止应用自带的 DoH 等其他解析方式。

### UDP 会话

| 选项 | 作用 | 自动值 |
|---|---|---|
| 映射方式 | 同一来源端口是否按目标 IP / 端口分别建映射 | endpoint_independent |
| 接收过滤 | 接受任意远端、仅已联系的 IP，或仅已联系的 IP 与端口 | endpoint_independent |
| 空闲超时 | 空闲多久后回收会话 | 5m |
| 会话上限 | 达到上限时淘汰最近最少使用的会话 | 内核根据内存选择 |

超时提供 1 / 5 / 10 / 30 分钟及自定义，支持 30s、5m、1h30m。会话上限提供 4096 / 8192 / 16384 及自定义；0 仍表示内核自动值。

这些参数控制 TUN 内部会话，不会让不支持 UDP 的 SSH / HTTP 出口获得 UDP 能力，也不保证公网 NAT 类型变成 Full Cone。

### 捕获范围与规则集

这里决定流量**是否进入 TUN**；进入后才执行域名、进程和节点等代理分流规则。

- route_address 留空使用默认范围，填写 CIDR 后使用指定系统路由。
- route_exclude_address 让指定 CIDR 绕过 TUN，适合局域网或现有 VPN。
- 捕获和绕过规则集支持多个名称，可搜索已知项，也可手动添加。
- 新规则集先添加来源，再选择名称。本地文件使用绝对路径，远程使用 HTTP(S) URL；二进制选择 SRS，源文件选择 JSON。
- 仅加载实际引用的来源；名称不得重复。用于系统路由的规则集必须包含目标 IP CIDR，域名规则不能替代系统路由。
- 关闭自动路由后，相应范围保留但不输出，不会自动开启父开关。

绕过 TUN 的流量可能直接使用原网络，需要确认绕过范围符合意图。

### Linux 高级

默认只在 Linux 显示。其他平台可查看只读说明，保存时不会输出 Linux 专用字段。

| 能力 | 依赖与说明 |
|---|---|
| 自动重定向 | 需要自动路由、nftables 和权限，默认不启用，用于改善接管及 Docker 网络兼容。 |
| 网卡筛选 | 需要自动路由；包含和排除互斥。严格路由还需考虑返回路径。 |
| UID 筛选 | 需要自动路由；单 UID 与 1000:1999 范围可组合。UID 0 表示 root。 |
| MAC 筛选 | 需要自动路由和自动重定向；包含和排除互斥，适用于网关。 |
| 命名空间 | 选择已有名称或路径；本页不创建、删除空间，目标空间网卡可能需手填。 |
| MPTCP 绕过 | 需要自动路由和自动重定向，开启后直接绕过代理，关闭时内核默认拒绝。 |
| 防火墙与路由编号 | 更多高级选项中配置输入 / 输出 / 重置 mark、NFQueue、路由表、规则起始和回退编号。 |

mark 支持十进制或 0x 十六进制；NFQueue 范围为 0–65535。自动值及每个字段用途在使用说明中列出。

## 模板、恢复与排障

- 完整 TUN 模板启用时，该模板拥有配置；本页只读并提供跳转，不会悄悄覆盖模板。
- TUN 由其他内核负责时，sing-box 专用选项保留但不可应用，页面说明原因。
- “恢复本组默认”只恢复当前可用平台的这一组；“取消修改”重新载入保存的 TUN 设置。
- 预检期间节点变化会停止应用，避免使用旧节点的检查结果。
- 先看字段错误、实际 TUN 内核及版本，再看日志中的变更和恢复原因。
- .local、DNS 分流、UDP 阻断和自身地址防回环继续由现有流程处理，修改后需按实际网络验证。

## 验证边界

界面截图和状态测试使用隔离配置，不启动真实内核。配置检查证明内核接受配置，不能替代实际接管证明。

Mac 独立冒烟入口：

~~~sh
python3 packaging/test-tun-macos.py --check-only --output /tmp/v2rayn-tun-check
sudo python3 packaging/test-tun-macos.py --output /tmp/v2rayn-tun-smoke
~~~

实际测试只捕获 198.18.77.0/30，不接管默认路由、不改系统 DNS。使用本机 TCP / UDP 回显与受控 DNS，覆盖三种协议栈及直接 / 前置 SOCKS 两条路径，退出检查测试路由恢复。真实启停需要本机管理员授权。

参考：[sing-box TUN](https://sing-box.sagernet.org/configuration/inbound/tun/)、[UDP NAT](https://sing-box.sagernet.org/configuration/shared/udp-nat/)。
