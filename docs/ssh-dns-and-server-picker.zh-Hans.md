# SSH DNS 与连接页服务器检测

SSH 节点编辑窗口的高级选项中增加“服务端 DNS”：部署并启用 / 接管、检测 DNS、回退、取消和详情。部署确认中列出主机、固定公钥、系统和出口；这是服务端即时操作，关闭编辑窗口不会撤销已提交部署。

部署限于 Ubuntu 24.04、systemd-resolved、Netplan/networkd 的 amd64/arm64 单链路布局。未知分流、同名服务、端口占用、出口不一致和外部配置漂移会拒绝接管。其他系统可使用独立 SSH DNS 检测。不会重启 SSH、resolved 或网络服务，不执行 netplan apply。

服务端独立目录为 `/opt/v2rayn/ssh-dns`，服务为 `v2rayn-ssh-dns.service`。固定 Ubuntu 包版本及 SHA256 位于嵌入的 `ssh-dns-helper.py`；只解包到私有目录，不安装或升级系统软件包。Unbound 仅监听 127.0.0.1 的 TCP/UDP 53，以 IPv4 递归并验证 DNSSEC，可返回 AAAA。已知阿里云内部域保留条件转发。

事务及原始文件备份位于 root 独占的 `/var/lib/v2rayn-ssh-dns-control`。候选解析器通过验证后才切换系统上游；准备阶段即启用 10 分钟回退计时器及开机恢复。提交、回退共用主机锁。回退先恢复原解析路径并确认可解析，再停止本次解析器；检测到漂移时保留备份及诊断，不覆盖外部修改。重试保留历史记录。可识别的 `/opt/ssh-egress-dns` 手工部署须通过服务、配置及原始备份校验，接管时不重启服务。

DNS 检测通过独立、固定公钥的临时 SSH 代理，使用三次随机新域名观察 IPLeak DNS 来源及前后 IPv4 HTTP 出口。只在来源集合恰好等于稳定出口时确认一致。网络错误、响应缺失、出口变化均为“无法确认”，不能提交部署。该结果只证明 SSH 远端 IPv4 解析路径，不代表当前客户端 TUN、浏览器 DoH 或 IPv6 DNS 的行为。

重复点击已提交部署只重新检测 DNS，不重装、重启或覆盖首次备份。已存在解析器时，resolved 的 Global 和主网卡同时列出同一个 `127.0.0.1` 不作为额外分流；外部全局上游、其他网卡 DNS 和无法识别的布局仍会拒绝。旧手工部署保留的 macOS 归档文件所有者只对固定路径、固定 SHA256、固定权限的 Unbound 配置兼容；原始备份、服务文件及父目录继续要求可信的 root 所有权，接管不修改文件所有者。

连接页“更换服务器”提供独立的分组和收藏筛选，可按名称、地址及分组搜索；同名分组按 ID 区分。列表虚拟化，名称、地址和检测结果分行显示。可检测单个节点或点击时的全部筛选结果，最多同时三个任务。TCP 连通性和通过节点的 HTTP 代理耗时分开记录；UDP-only 节点的 TCP 项为“不适用”。HTTP 非成功响应、失败、超时和取消分别显示。检测不切换节点、不下载测速、不改变系统代理。关闭选择器或切换连接取消测试，节点被编辑或订阅重建后旧结果不再写入。

本轮验收记录及已知环境限制在工作区 `artifacts/local-ssh-dns-picker-20261117/VERIFICATION.md`。VM 本地域名夹具仅用于验证 systemd/Netplan/回退事务，不能替代公网递归和 DNS 出口一致性验收。
