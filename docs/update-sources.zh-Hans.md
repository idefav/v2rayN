# 更新与资源来源

在 **设置 → 更新与资源来源** 配置 v2rayN、Xray、mihomo、sing-box 和三个规则来源。更新页面也提供此设置的入口。Windows WPF 与跨平台 Desktop 共用配置。

| 项目 | 留空时使用 |
| --- | --- |
| v2rayN | `2dust/v2rayN` |
| Xray | `XTLS/Xray-core` |
| mihomo | `MetaCubeX/mihomo` |
| sing-box | `SagerNet/sing-box` |
| Geo 数据 | 内置 `Loyalsoldier/v2ray-rules-dat` 下载模板 |
| sing-box SRS | 内置 `2dust/sing-box-rules` 下载模板 |
| 路由规则模板 | 程序内置路由模板 |

程序来源接受 `owner/repo`、`https://github.com/owner/repo` 或其 `/releases` 链接。例如内部 SSH UDP 核心填写 `idefav/sing-box`。仓库必须公开，并提供符合原程序文件名和平台目录结构的 Release 资产；仅上传源码不能用于在线更新。支持四项程序各自选择是否包含预发布版本，不支持私有仓库令牌或自建版本 API。

Geo URL 模板使用 `{0}` 表示 `geoip` 或 `geosite`。SRS URL 模板使用 `{0}` 表示类别、`{1}` 表示带类别前缀的规则名（如 `geoip-cn`）、`{2}` 表示原始规则名（如 `cn`），兼容只用 `{1}` 的现有预设。路由规则填写模板 JSON 的下载 URL。已有规则来源配置及地区预设继续有效。

## 保存与恢复默认

每项可单独恢复默认，也可以全部恢复默认。按钮只修改当前草稿，点击保存才生效，取消会放弃修改。全部恢复默认仅清空这七项自定义来源，不修改节点、现有路由、DNS、更新代理或预发布选项。

保存来源不会下载软件、切换核心或重启代理。路由模板恢复默认仅影响后续路由初始化，不覆盖已保存规则。Geo 恢复默认后沿用原有附加 Geo 文件下载行为。

## 更新和来源切换

同一来源仅提示更高版本。切换仓库时，可以点击“检查并更新”安装目标仓库的相同或较低版本，页面会标明“切换来源”；后台检查始终只提示。恢复默认后，正在运行的自定义核心会保留，直到手动执行更新。

更新按照原始 Release tag 匹配当前系统和 CPU 的资产，保留 Windows WPF/Desktop、mihomo CPU/ABI 等区别。没有匹配资产或请求失败时报告错误，不偷偷切回默认仓库。操作开始后使用来源快照，不混用操作中修改的地址。系统安装包原有的应用内更新限制继续适用。

核心更新解压到用户目录 `bin/updates/<核心>/`，验证实际版本、依赖和当前配置后激活；启动失败恢复前一选择。已安装来源由成功安装记录标识；旧安装无法判断的来源显示“未知”，手动更新后建立记录。

sing-box 的选择顺序是：校验有效的显式更新核心、有效随包专用核心、原用户目录核心。版本检测、运行和测速使用相同选择逻辑。原版核心不能加载当前 SSH UDP 扩展配置时，更新会报不兼容并保留旧核心，不删除用户配置。

v2rayN 应用仍由升级助手替换。下载完成不代表升级成功；新启动的程序与下载包中的可执行文件 SHA-256 一致后才确认来源。CI 构建携带构建仓库和发布标签，后续安装的预发布版本可正确比较。

## 隔离验证

服务测试涵盖配置恢复、资产匹配、安装记录损坏和回滚。设置 `V2RAYN_UPDATE_TEST_CORE` 为真实 sing-box 的绝对路径，可在临时目录验证安装、实际启动和失败回滚；不会替换该路径的文件。

UI 验证程序支持 `--update-sources-only --headless`，使用独立测试配置检查七项来源、草稿、保存、恢复默认、配置重载及无核心重载行为，并输出页面截图。
