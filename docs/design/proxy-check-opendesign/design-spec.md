# v2rayN Proxy Check — Egress Diagnostics

## 交付与边界

- 原型入口：`index.html`，无构建依赖，可直接用浏览器打开；全部样式、图标和脚本内嵌，离线可用。
- 本文为可编辑设计规格，供 Avalonia 页面重构参考；没有修改 v2rayN 源码或系统网络设置。
- 所有节点、时刻、连接、签名、采样和诊断结果均为**设计演示数据**。未执行网络请求、密码学验证或真实出口检查。签名证据为示意，不是验证成功的证明。
- 默认中文、浅色、部分失败示例，以便同时查看通信正常、出口不匹配、服务故障及覆盖边界。页脚“演示状态”是本次明确要求的原型操作；生产客户端移除此控件和演示标识。
- 视觉方向来自用户指定的 v2rayN 外壳和桌面工具要求；未另加品牌系统、宣传版面或营销图像。

## 1. 信息架构

1. 固定 72px 图标导航，盾牌为当前页面；其他图标仅保留已有外壳位置，不建立未请求的产品页面。
2. 72px 顶栏：v2rayN / 连接与诊断；右侧演示标识、主题、语言。
3. 页面标题：代理检查；说明强调通信路径、出口和证据。状态与标题同排，避免埋在长日志中。
4. 操作区：开始检查为唯一实心主操作，检查中原位替换为取消；重试失败、导出报告为描边次要操作；基线为菜单。
5. 环境区：节点、核心、网络接管、路由、本地入口。独立服务区域展示精确出口服务连接状态、IPv4 覆盖、IPv6 未覆盖及配置入口。
6. 本轮概览：通信正常、出口匹配、需关注、未覆盖；不使用全局“通过率”混淆维度。
7. 高密度结果：TCP/TLS、DNS、UDP、HTTP3、IPv6、网络接管。分组折叠、筛选、搜索、行展开证据。
8. 页脚：演示边界说明和五种状态选择。

## 4. 诊断状态模型

禁止用一个 `IsSuccess` 同时代表通信、出口、覆盖和配置正确性。建议独立维度：

| 维度 | 值 | 呈现 |
| --- | --- | --- |
| 运行 | Idle / Running / PartialFailure / Completed / Canceled | 标题标签、主按钮、进度 |
| 通信 | Pending / ResponseReceived / Failed / ReturnPathFailed / Unsupported / NotApplicable / Uncovered | 图标 + 文字 + 已收完整响应次数 |
| 观察 | None / SignedClientEgress / RecursiveResolverEgress / LocalConfiguration | 实际地址下的来源标签 |
| 预期 | Match / Mismatch / ObservedWithoutExpectation / NoObservation / NotApplicable / Unsupported / Uncovered / Pending | 独立比较列 |
| 失败阶段 | Connect / TLS / Request / Observer / ReturnPath / ResponseRead | 详情明确阶段和原因 |

### 判定约束

- 通信成功不代表出口匹配。UDP 例：3/3 完整响应，实际 `198.51.100.7`，预期 `203.0.113.0/24`，出口不匹配。
- 正常示例实际 `198.51.100.7`，默认全局预期同为 `198.51.100.7`；不得将其判为匹配 `203.0.113.0/24`。
- 原型分流规则采用“检查 ID → 地址”，例如 `udp-tun → 203.0.113.0/24`；按项规则优先于全局预期。此语法是交互演示格式，不代表 v2rayN 现有配置格式。
- 本原型仅接受用户指定的示例地址与网段，不承担通用 IPv4/IPv6/CIDR 解析。生产实现必须使用 IPAddress 与 CIDR 掩码计算。
- 加密 DNS 展示签名观测，但刻意不配置预期，显示“已观测·未配置预期”。全局预期不覆盖语义上未指定比较策略的 DNS 演示项。
- 系统 DNS 只展示“递归解析器出口”，比较为“不适用”。权威 DNS 所见地址不可当作客户端到 DNS 服务出口。
- 系统代理设置、SSH 能力只描述配置或能力，本身无公网流量，出口为“不适用”。
- HTTP CONNECT 的 UDP 为“不支持”，不计失败。
- IPv4-only 观察端的两个 IPv6 项为“未覆盖”，不计失败，不暗示 IPv6 被阻断。
- 公共服务项示例返回 HTTP 503，属于应用探测失败；证据明确服务异常，建议重试或换观察端，不判断泄漏。
- HTTP3 项展示观察端收到 3/3 请求，但客户端完整响应 0/3，通信为“回程未通”。其出口观测仍能单独匹配。原型中的观察端回执来自预置数据；生产必须有可信独立证据通道，不能从超时猜测服务已收到。
- 重试失败只重试通信失败、回程失败；出口不匹配需检查预期和路由后重新整轮检查。
- “完成”表示调度结束且无通信失败，仍可能有出口不匹配。不得把标题完成状态解释为全部出口符合预期。

### 概览口径

- 通信正常：完整响应 3/3，不含单纯配置检查。
- 出口匹配：有客户端签名观测且与该项有效预期相符；可以与回程失败交叉计数。
- 需关注：通信失败、回程失败、出口不匹配的并集；每项最多计一次。
- 未覆盖：观察端无法覆盖的检查项；不包含不支持、不适用。
- 默认 15 项部分失败样例：通信正常 **8**、出口匹配 **6**、需关注 **3**、未覆盖 **2**。计数从行模型生成，不是独立写死的仪表数字。
- 空闲：概览全为“—”，行显示等待检查，不展示已成功的结果。

## 5. 交互约定

### 开始、取消、重试

- 开始清除当前演示结果，固定本轮预期与分流规则快照，每 650ms 完成一项并更新进度；这是演示调度时间，不是实际测速。
- 取消停止后续调度，保留已完成行；未执行项保持等待，不伪造失败。
- 页脚取消样例预置前六项完成；实际点击取消保留点击时的实际数量。
- 重试模拟 900ms 等待并禁止重复点击，只替换失败项的演示结果。
- 设置变更在下一轮生效，不回写当前轮证据。
- 结果筛选：通过仅限通信正常且出口匹配；“已观测·未配置预期”、不适用、不支持留在全部中，可通过搜索找到。

### 证据展开

- 点击整行或键盘 Enter/Space，展开原位详情：来源、失败阶段、观察类型、有效预期、基线比较、三次采样与具体建议。
- 行与详情通过 `aria-expanded`、`aria-controls` 关联；详情展开不改变路由。
- 所有功能图标配可访问名称或相邻文本；状态同时使用符号、文本与颜色。

### 服务配置

- 可见字段：端点、密码式访问凭证、可选预期、分流规则、采样 3 次、常规超时 5s、HTTP3 超时 10s、观察覆盖。
- JSON 位于高级折叠区，默认关闭；凭证固定遮挡。可以应用 JSON 到表单或导入本地 JSON，再保存。
- 导入只读取用户选择的文件；不更改原文件。非法 JSON 或字段值显示相邻错误。
- 测试连接明确是演示反馈，约 900ms 后显示模拟签名格式与 IPv4 状态；没有真实 fetch。
- 表单保留可见标签，必填 URL 与超时利用原生校验；保存时验证演示地址和分流规则。
- 凭证、配置、基线均仅在页面内存；刷新清除，不使用 localStorage、cookie 或后端。

### 基线与导出

- 整轮完成后允许保存基线；内存中保存全局预期、各项比较结果与时间。选择基线将保存的全局预期用于下一轮，详情显示比较结果是否变化。
- 此原型基线不冻结整份网络配置或分流规则；生产建议保存规则、节点标识、核心版本和观察端身份摘要，明确版本与比较范围。
- 导出按钮下载 JSON 演示报告，包含演示声明、运行状态、时间、每项结果及预期。不会自动在项目生成额外文件。
- 导出不含访问凭证，不含原始配置全文。原型选择 JSON 便于开发者和运维取证；未请求 PDF 或额外可视化报告。

## 6. Avalonia 实现建议

### 页面结构

- 外层 `Grid Columns="72,*"` 复用既有导航；主区用 `ScrollViewer` 和纵向布局承载标题、环境、概览、结果。
- 运行环境使用 Grid，服务块独立 DataTemplate。不要把整个环境拼成长字符串。
- 主按钮绑定 `StartOrCancelCommand`，按运行态切换图标和标签。次要命令绑定 `CanExecute`；运行中禁用重试，未有结果时禁用导出。
- 基线采用 `Flyout` 或菜单，设置采用模态 `Window` / DialogHost；高级 JSON 使用 `Expander`。凭证使用 PasswordChar，不参与自动保存和日志输出。
- 列表建议虚拟化 `ItemsRepeater` / `ListBox` 与分组头模板；宽窗共享列宽，窄窗换 DataTemplate。不要每行建一个完整大卡片。
- 详情按需创建，避免每个折叠项都保留复杂可视树。

### ViewModel

建议 `ProxyCheckViewModel` 持有 `RunState`、`ObservableCollection<CheckResultViewModel>`、`CompletedCount`、`TotalCount`、`Filter`、`SearchText`、`ObserverSettingsViewModel` 和内存基线。

每条结果独立记录：

```text
CheckId, Group, Protocol, Target, PathKind
ConnectivityStatus, ResponseCount, SampleCount
ObservationKind, ObservedAddress, ObserverIdentity
ExpectedAddressOrCidr, ExpectationStatus
Duration, FailureStage, FailureReason
Samples[], Suggestions[], StartedAt, FinishedAt
RequestReceivedByObserver, ResponseReceivedByClient
IsExpanded, IsDemo
```

- `Samples[]` 区分观察端接收时间与客户端响应时间，不能只用一个 Success 布尔值。
- 保存本轮环境和预期快照，结果只依赖该快照，防止配置变更让旧证据瞬时翻转。
- 汇总从同一批结果派生，筛选不改变概览；使用批量更新减少 UI 线程重绘。
- CancellationTokenSource 只取消当前调度和未完成请求，已返回结果保留；重试需要记录 attempt/run 关系。
- 服务响应签名应验证身份、时间、随机数及请求关联；验证失败不能标为可信出口观测。
- 公共服务故障、代理连接错误、TLS 失败、UDP 不支持、观察能力不足各用独立错误类型，避免统一红色“失败”。
- 中英文使用资源文件；颜色与字号使用 DynamicResource，主题采用 Light/Dark ResourceDictionary。等宽字体提供各平台 fallback。
- 生产网络能力应继续复用既有诊断引擎，不让 ViewModel 直接更改系统代理、TUN 或路由设置。

## 7. 当前实现范围
