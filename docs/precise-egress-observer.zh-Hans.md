# 独立出口探测服务

服务端独立仓库：[idefav/egress-probe](https://github.com/idefav/egress-probe)。客户端 Go worker 固定引用 SDK 版本；服务端自行部署，不在桌面客户端监听服务端口，也不改动已有 SSH 或代理服务。

## 使用

1. 按服务端 README 部署 Linux IPv4 观察端，完成 DNS 子域委派和端口放行。
2. 在“代理检查 → 独立出口探测服务”导入通过可信渠道取得的 `profile.json`。
3. 启用受控探测，填写 API 凭证，测试控制接口，然后运行完整检查。
4. 配置预期 IP/CIDR；分流规则可使用 `目标|协议|路径=IP/CIDR`，路径为 `socks`、`native`、`http-connect`、`system`。精确规则优先于目标及全局规则。

预览版 API 凭证仅保存在内存，不写入配置、报告和基线。需要重启后重新输入。不要分享私有配置、API 凭证或签名私钥。

## 证据与判定

- TCP/TLS、HTTP/HTTPS、普通 UDP、STUN、真实 HTTP3 使用与本次采样绑定的服务端观测，校验固定公钥签名。
- SOCKS、HTTP CONNECT、系统 HTTP 和原生套接字/TUN 分开检查，HTTP CONNECT 不支持 UDP 时不会改走其他路径。
- 每次采样单独保留源 IP/端口、协议、时间及签名。预期不同的项目单独判断，任意确认的不匹配不能被其他失败采样掩盖。
- 无预期时展示“已观测，未配置预期”；通信成功不自动证明出口符合要求。
- 系统代理设置、SSH 扩展协商不产生公网出口，显示“不适用”。
- 系统/本地 DNS 到权威服务的观测是递归解析器出口。客户端到第三方递归器的源 IP 需要那个接收端配合，不能推断。FakeIP/本地合成可能没有权威查询。
- 直达受控 DNS 的 UDP、TCP、A/AAAA、NXDOMAIN、截断重试分别保留证据。测试用 AAAA 地址不是 IPv6 可用性结论。
- 首版观察端只有 IPv4，IPv6 传输出口显示未覆盖。
- 超时仍可能取得签名入站记录，这只证明请求到达，不代表双向协议成功。服务故障不直接认定泄漏，也不静默切回公共端点。

报告版本为 2，仍可导入版本 1 基线，旧版标明未经签名验证。使用服务端 CLI 和单独可信的公钥配置可离线验证历史报告：

```sh
egress-probe-server -verify-report proxy-check-report.json -profile trusted-profile.json
```

## 部署选择与验收边界

用户指定的美国独立机器可用于观测新加坡等其他出口，不能用来验收该美国机器自己的代理出口。测试预期与观察服务器相同时，客户端阻止验收。服务标识和签名密钥变化需要重新导入配置。

部署前确认 TCP 53/80/443/18080/18443 与 UDP 53/443/3478/3479 没有冲突。不要接入 CDN 或修改源地址的反代。

需要独立服务器、可委派的测试域名及有效 TLS。没有完成公网部署前，本机 fixture 通过只表示实现测试通过，不等于实际国内、香港中继已验收。

## macOS 安装

不自动替换正在使用的客户端。从匹配版本 release 分支构建测试包后自行安装。确认来源可信且系统拦截时，只处理该应用：

```sh
sudo xattr -dr com.apple.quarantine "/Applications/v2rayN.app"
```

WebRTC/浏览器 DoH、断网保护、网络切换、长连接、局域网/.local、大 UDP 包与 MTU 仍不在本轮覆盖范围内。
