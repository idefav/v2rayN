# V4：独立连接窗口、设置窗口与菜单栏

本轮沿用 Local Codex 项目 `v2rayn-inline-connection-20261112` 的 V4 设计，保留 V2/V3 对照和全部设置管理页面。未提交或推送，没有操作已安装客户端、用户配置或系统网络。

## 窗口与授权

- 连接窗口默认 440×620，最小 360×480；设置默认 1120×780，最小 800×600，按显示器工作区域约束首次尺寸。两者分别使用 `ConnectionWindow` / `SettingsWindow` 的现有窗口尺寸记录。
- 设置使用独立且复用的 Window，管理内容及绑定仍来自原有 Workspace。重复打开激活现有实例；连接窗口快捷入口不丢弃设置草稿。关闭设置走原有保存、放弃、取消流程，不断开连接。应用退出继续走既有退出协调器。
- 两个窗口的 DialogHost 有各自标识。授权固定在可见连接窗口，节点分享跟随设置宿主，防止双宿主歧义。授权表面不透明，正文滚动、底部按钮固定；密码验证期间禁用重复提交，失败就地显示，取消清空输入并阻止迟到结果关闭新对话框。
- 连接窗口的实时速度选择可在设置草稿打开时修改。保存其他应用选项时，未编辑的速度和统计字段保留最新实际配置，避免旧草稿回写。

## 菜单栏

`WorkspaceTray` 替换旧菜单栏图标与菜单。P 是实际系统代理状态，T 是实际 TUN 状态；实心表示开启，空心表示关闭，问号表示无法确认。使用单色模板位图，不依赖红绿颜色。

- macOS 系统代理通过有界、只读的 `scutil --proxy` 查询。识别本机端点、其他代理/PAC、关闭和未知；忽略不代表全局默认代理的 scoped 字典。所选代理策略仅显示子菜单勾选，不当作实际结果。
- TUN 来源于已验证运行快照以及主/前置内核存活检查。记录未确认或查询失败时显示未知，不能因为选中 TUN 就显示运行中。
- 连接/断开、TUN、重新连接和代理策略复用现有 ViewModel 操作，转换过程中禁用重复操作。打开连接、设置、复制终端代理、剪贴板导入、直连/代理更新订阅、退出均有入口。
- 非 macOS 当前没有新增系统代理观测器，实际代理状态明确显示未知，不伪造为关闭。

## 回归与交付

`v2rayN.Desktop.Review --workspace-v4-only` 覆盖双窗口尺寸/复用/草稿关闭、两窗口设置冲突、授权小尺寸/主题/焦点/失败/取消/迟到结果、隐藏窗口唤起、菜单状态/命令/忙碌守卫及 P/T 像素边界。Review 的 Opened 回调只执行一次，隐藏再显示不会重入测试。

既有 V3 和完整管理界面回归已迁移到实际设置窗口的视觉树、坐标和键盘目标；主连接控件仍从连接窗口获取，不使用旧的单窗口假设。

本轮实际通过与未执行的范围、DMG 校验和、设计与客户端截图见工作区 `artifacts/local-workspace-v4-20261113/VERIFICATION.md`。所有真实连接、sudo 授权、TUN、系统代理写入、订阅下载与更新安装均未执行；原生窗口回归使用隔离夹具。

## 2026-11-13 启动崩溃修复

已发布给用户的首个本地 V4 包在 macOS 启动时抛出 `The menu being updated does not match`。`App.axaml` 已将菜单根对象交给原生 exporter，`WorkspaceTray` 再赋值一个新根对象导致未处理异常。现在复用已注册根对象，只替换其条目；仅当新 TrayIcon 没有菜单时创建并赋值一次。

新增 `v2rayN.Desktop.Review --startup-only`，在隔离的空配置目录运行生产 `App.OnFrameworkInitializationCompleted` 和真实 `MainWindowViewModel` 初始化；禁止系统代理和自启动修改，不放入真实节点，不启动内核。该回归直接使用 XAML 创建的菜单，覆盖原生初始化、周期刷新、界面心跳以及打开设置。旧实现已在原生环境复现同一异常，最终修复在原生及 Headless 均通过。CI 增加对应启动回归，macOS 额外运行原生路径，未推送执行远端工作流。

原生补跑还修正了授权容器取得焦点时未恢复密码输入焦点的问题；加载后的焦点请求采用 Loaded 优先级，且不拦截子控件的正常焦点。设置侧栏滚动与键盘聚焦分开：窗口尚未激活时仍将当前条目滚入可见区域，键盘焦点仍遵守活动窗口和对话框保护。

本次实际验证记录与新镜像位于 `artifacts/local-workspace-v4-startup-fix-20261113/`；旧包保留用于追踪，不再作为本次交付包。
